## Objective

Add a gamified, button-driven wizard panel above the Workshop composer that lets users build and iterate on a prompt without typing. A hardcoded section scaffold (Subject -> Scenery -> Lighting -> Mood -> Style) drives the intro, but every option button is generated by the LLM. From there, the user iterates by clicking persistent action verbs (Improve / Change / Add / Remove / Surprise) and LLM-suggested context buttons. The wizard always emits a **draft string** into the composer; it never auto-creates session nodes. State is persisted per Workshop session (with one unbound slot when no session is active) so navigating away and back restores the in-progress wizard.

## Data Model

```csharp
// BlazorWebApp/Data/Entities/WorkshopWizardSession.cs
public class WorkshopWizardSession
{
    public int Id { get; set; }

    /// <summary>Optional FK. Null = unbound slot used when no Workshop session is active.</summary>
    public int? SessionId { get; set; }
    public PromptWorkshopSession? Session { get; set; }

    /// <summary>JSON-serialized WizardBody via ValueConverter (single-complex-column pattern).</summary>
    public WizardBody Body { get; set; } = new();

    public DateTime CreatedAt { get; set; }
    public DateTime UpdatedAt { get; set; }
}

// BlazorWebApp/Models/WizardModels.cs
public enum WizardStage { Intro, Iteration, Committed }

public sealed class WizardBody
{
    public WizardStage Stage { get; set; } = WizardStage.Intro;
    public int IntroSectionIndex { get; set; }                  // 0..(IntroSections.Count-1)
    public int TurnCount { get; set; }                          // hard cap 50, nudge at 30
    public string CurrentDraft { get; set; } = "";
    public string? PendingQuestion { get; set; }                // last LLM question
    public List<WizardOption> PendingOptions { get; set; } = new();
    public List<string> LastShownLabels { get; set; } = new();  // sent to "More..." for excludeLabels
    public List<WizardTurn> History { get; set; } = new();      // deterministic Undo + last-N context
    public string? LastActionVerb { get; set; }
}

public sealed class WizardTurn
{
    public string Source { get; set; } = "";        // "intro:subject" | "iterate" | "verb:add" | "more"
    public string Question { get; set; } = "";
    public List<WizardOption> Options { get; set; } = new();
    public string Choice { get; set; } = "";
    public string? ActionVerb { get; set; }
    public string DraftBefore { get; set; } = "";
    public string DraftAfter { get; set; } = "";
}

public sealed class WizardOption
{
    public string Label { get; set; } = "";   // <= 60 chars
    public string? Hint { get; set; }         // <= 80 chars
    public string? Payload { get; set; }      // optional richer payload sent back to the LLM
}
```

## LLM Contract (JSON Mode)

All LLM calls in this phase request `format: "json"` and target the same response shape:

```json
{
  "question": "What kind of subject feels right for today?",
  "options": [
    { "label": "An ancient courier owl", "hint": "feathers like parchment" },
    { "label": "A retired astronaut gardener", "hint": "weightless tomatoes" },
    { "label": "A child cartographer of dreams", "hint": "ink-stained fingers" }
  ]
}
```

### Request payload shape (informational)

```jsonc
{
  "stage": "intro" | "iterate" | "more" | "verb",
  "section": "subject",                  // intro only
  "guidance": "...",                     // intro only (from wizard_intro.json)
  "examples": ["...", "..."],            // intro only
  "currentDraft": "...",                 // omitted when empty
  "verb": "add",                         // verb stage only
  "lastTurns": [                         // last 1-2 turns max
    { "question": "...", "choice": "...", "draftAfter": "..." }
  ],
  "excludeLabels": ["..."]               // "more" stage only
}
```

### Schema constraints (in system prompt)

- 3-6 options per turn.
- `label` <= 60 chars, no trailing punctuation.
- `hint` optional, <= 80 chars.
- No prose outside the JSON object.
- For `excludeLabels`, the response MUST NOT contain any listed label (case-insensitive).

### Failure handling

- Parse failure -> retry once with the stricter prompt suffix `"Return ONLY the JSON object."`.
- Second failure -> snackbar `"Suggestions unavailable - use the action buttons below"` and keep the persistent verbs functional.

### Step 4: `WorkshopWizardService` (state, turns, undo, commit)

**Complexity:** 8
**Status:** [ ] Not Started

#### Tasks

- [ ] `IWorkshopWizardService` + `WorkshopWizardService` registered as singleton in `Program.cs`.
- [ ] `LoadOrCreateAsync(int? sessionId)` returns the existing row or creates a new `WorkshopWizardSession` with `Body.Stage = Intro`.
- [ ] `AdvanceIntroAsync(int? sessionId, WizardOption choice)`:
  - Append turn (`Source = "intro:{sectionId}"`).
  - Update `CurrentDraft` (intro draft built by stitching choices with section delimiters; first pass uses local templating, no LLM cost).
  - When the last section is consumed, transition `Stage = Iteration`.
  - Request next section's options via `OllamaService` `format: "json"` using the section guidance + examples; persist results into `PendingQuestion` / `PendingOptions` / `LastShownLabels`.
- [ ] `AdvanceIterationAsync(int? sessionId, WizardOption choice)`:
  - Append turn (`Source = "iterate"`).
  - Send `currentDraft + last 1-2 turns + choice` to LLM with the iteration system prompt.
  - Update `CurrentDraft` from the LLM's draft revision (response also returns `draft` field; see Step 6 prompt design).
  - Refresh `PendingOptions`.
- [ ] `ApplyVerbAsync(int? sessionId, string verb)`:
  - For Improve / Change / Add / Remove / Surprise: call dedicated system prompt; LLM returns updated draft + new `{ question, options }`.
  - Append turn (`Source = "verb:{verb}"`).
- [ ] `RequestMoreAsync(int? sessionId)`:
  - Re-call the iteration prompt with `excludeLabels = LastShownLabels`.
  - Replace `PendingOptions`; merge into `LastShownLabels` to widen the exclusion set.
- [ ] `UndoAsync(int? sessionId)`:
  - Pop last `WizardTurn`, restore `CurrentDraft = turn.DraftBefore`, restore `PendingQuestion` / `PendingOptions` from the prior turn or from the row's snapshot.
  - **No LLM call.**
- [ ] `CommitAsync(int? sessionId)`:
  - Set `Stage = Committed`; raise `WizardCommittedEventArgs` with `CurrentDraft`.
- [ ] `ResetAsync(int? sessionId)`:
  - Wipe `Body` to a fresh intro state; raise `WizardResetEventArgs`.
- [ ] Enforce `TurnCount` cap (50 hard, 30 soft via event args flag).
- [ ] After every mutation: `entry.Property(e => e.Body).IsModified = true; UpdatedAt = DateTime.UtcNow; SaveChangesAsync()`.
- [ ] Context-trimming helper `BuildContextWindow(WizardBody body)` returns at most last 2 turns; covered by unit test.

#### Done When

- Service unit tests cover: LoadOrCreate, intro advance, iteration advance, verb apply (mocked Ollama), more (excludeLabels honored), undo, commit, reset, turn cap.
- Each public mutation persists `Body` and bumps `UpdatedAt`.

## Stress Points & Mitigations

| Risk | Mitigation |
|------|------------|
| Small models produce malformed JSON | `format: "json"` + strict schema in system prompt + single retry + snackbar fallback (Steps 6 & 10) |
| Context creep across turns | Hard sliding window of last 1-2 turns enforced by `BuildContextWindow` (Step 4) |
| Per-session FK + unbound null slot creates two code paths | Single `LoadOrCreateAsync(int?)` + filtered unique index (Step 1) |
| Repetition of LLM options | `excludeLabels` rule and "More..." rotation (Step 4 + Step 6 prompts) |
| Seeded prompts drift from schema | Version stamp + re-seed loop in `DatabaseService` (Step 6) |
| Undo destabilizes the LLM continuity | Undo never calls LLM; restores `Body` snapshot deterministically (Step 4) |
| Composer keyboard collisions | Panel is buttons-only; no keyboard handlers (Step 7) |
